# Plan: refresh OKF catalog indexes (`eru okf init --update [--force]`)

> On "implement", copy this file to `plans/okf-index-refresh.md` (AGENTS.md convention; plan mode only allows writing this file).

## Context
`eru okf init` only creates missing `index.md` files and never overwrites (`OkfFix.execute`, `src/Eru.Domain/OkfFix.fs:258`: `if not (hasIndex dir)`). `okf fix` has the same gap: it only generates missing indexes. After a concept is added, removed or retitled, its folder's catalog table goes stale and nothing detects or repairs it. We want:
1. A way to regenerate only the machine-owned catalog part of an index, leaving hand-written content alone.
2. A `--force` to adopt index files that predate the markers, but only when the file is genuinely an OKF index and not some other file called `index.md`.

## Design

### Catalog markers
Generated catalogs (the `## Folders` list and the `| Concept | Type | Tags | Stale after |` table from `catalogBody`, `OkfFix.fs:113`) are wrapped in `<!-- eru:catalog -->` … `<!-- /eru:catalog -->`. New indexes get the markers. Refresh replaces only what lies between them. Validate must accept the markers (HTML comments, so no validate impact expected; confirm).

### Behaviour matrix
| Index state | `--update` | `--update --force` |
|---|---|---|
| Has marker pair | regenerate the block | same |
| No markers | skip, report `skipped: no eru:catalog markers (use --force)` | migrate (below), then regenerate |
| Missing | create with markers | same |
| Fails identity check | skip, report reason | skip, report reason (never overridable) |

Unmatched or duplicated markers (one open without close, or more than one pair) are reported `skipped: malformed markers` and never rewritten, even with `--force`.

### Migration of an unmarked index (`--force`)
- If the file has a markdown table whose header matches eru's generated header (`| Concept | Type | Tags | Stale after |`), replace that table (and an adjacent `## Folders` list generated by eru, if present) with the marked block.
- Otherwise append a marked block at the end of the file. Never replace an unrelated table.
- Prose, headings and root `okf_version` frontmatter are untouched. Never rewrites the file wholesale; a full rewrite is delete + `init`.
- Only write when content changes; idempotent on a second run.

### Identity check: "is this an OKF index?"
New pure module `src/Eru.Domain/OkfIndex.fs`:
`classify : Deps -> rel:string -> content:string -> Result<OkfIndexKind, NotIndexReason>` with `OkfIndexKind = Root | Folder`. All must hold:
1. **Inside a bundle.** The command path is the bundle root, and its `index.md` must carry `okf_version` (same marker `SourceAdd` `--scan` uses; see `Frontmatter.okfVersion`, `Frontmatter.fs:88`). A root without `okf_version` makes nested indexes fail with `outside bundle` plus hint "run `eru okf fix` first". `--force` never adds `okf_version` itself (that opts a directory into being an OKF bundle).
2. **Frontmatter shape.** Root: only `okf_version`. Non-root: no frontmatter. Same rules as `validateIndex` (`OkfValidate.fs:21`); extract/share that predicate rather than duplicating. Otherwise `foreign frontmatter`.
3. **Not ignored.** Not matched by `Patterns.isOkfIgnored` with `Config.resolveOkfIgnorePatterns` patterns (already applied in `execute` via `rels`). Otherwise `ignored path`.
4. **Folder has something to catalog.** At least one concept (`Frontmatter.classifyContent` = `ConceptFile`) or subfolder in `dirs`. Otherwise `empty folder`.

`init --update`, `fix` and the validate warnings all call this so they agree on what an index is. Reuse `Frontmatter.classifyFile` for the `IndexFile` classification.

### Domain (`src/Eru.Domain/OkfFix.fs`)
- Add `Update: bool` and `Force: bool` to `Command` (default false; `Fix` mode implies update, force still opt-in).
- Split `catalogBody` into body generation + `wrapCatalog`. Add `refreshIndex` (marker find, replace, migrate), pure and unit-testable.
- In the directory loop (`OkfFix.fs:252`): when `hasIndex dir`, and `Update`, run `OkfIndex.classify`, then refresh or migrate per matrix. Record `Change` with new rules: `index-refreshed`, `index-migrated`; skips go into a new `Skipped: (path * reason) list` on `FixResult` (not `Manual`, which makes `fix` exit 1).
- Honour `DryRun` through the existing `write` helper.

### Validate (`src/Eru.Domain/OkfValidate.fs`)
Non-fatal warnings (exit code unchanged unless `--strict-links`-style strictness is later added): `missing-catalog-markers` (identified OKF index without markers) and `stale-index` (block differs from a freshly generated one). Reuse the same generator as refresh so they cannot disagree.

### CLI (`src/Eru.Cli/`)
- `Args.fs` (`OkfInitArgs`, ~line 715): add `Update` and `Force` (`Force` requires `Update`; error otherwise). `OkfFixArgs` gets no new flags: `fix` always refreshes marked indexes and prints a hint to run `init --update --force` for unmarked ones.
- `OkfInitCli.fs`: pass flags through to `OkfFixCli.runMode`.
- `OkfFixCli.fs`: print per-index status `refreshed | unchanged | migrated | skipped (<reason>)` in all output formats (`OutputFormat.fs`).

### Ingestor template
`agents/ingestor.agent.md`: after adding concepts, run `eru okf init --update` instead of relying on `init` for new folders only; keep `validate`/`fix` as the final check. Update the generated index shape if documented there.

### Docs and housekeeping
`CHANGELOG.md`, `docs/reference/cli.md` (`okf init` section), `README.md:119`, `skills/eru/references/commands.md`.

## Tests (`tests/Eru.Tests/`, reuse fake `Deps` from existing `OkfFix`/`OkfValidate` tests)
- Marked index: only the block changes; prose before/after byte-identical.
- Unmarked: skipped without `--force`; migrated with it (table replaced when header matches, block appended when it does not; unrelated table untouched).
- Identity check: one case per reason (`outside bundle`, `foreign frontmatter`, `ignored path`, `empty folder`); file byte-identical after `--force`.
- Malformed/duplicate markers skipped even with `--force`.
- Idempotent second run; `--dry-run` writes nothing; `init` without `--update` still never overwrites.
- Validate: `missing-catalog-markers` and `stale-index` raised, and cleared after `init --update --force`.

## Verification
- `dotnet build` and `dotnet test` from the repo root.
- Manual (scratchpad copy of a sample bundle): add/rename a concept; `eru okf validate` shows `stale-index`; `eru okf init <dir> --update --dry-run`, then without `--dry-run`; validate is clean. Repeat on an index without markers (skipped, then `--force` migrates). Place a foreign `index.md` (with `layout:` frontmatter) in a subfolder and confirm `--force` leaves it untouched and reports why.

## Open items to resolve at implement time
Resolved with the user:
1. The generated `## Folders` list is replaced on migration (together with the matching table).
2. `--force` lives on `init --update` only (confirmed; `fix` refreshes marked indexes and hints at `init --update --force` for unmarked ones).
3. Root index with no `okf_version` and no other frontmatter: nested indexes report `outside bundle`, with a hint to run `fix`. Accepted.
